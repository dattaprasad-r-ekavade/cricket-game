# Review — 6 October 2026

Reviewed the current single-over game and batting tools starting at `45bcd5d`. The review fixes are covered by repeatable local checks; this is not a certification of all gameplay or of the intended visual target.

## Findings addressed

| Priority | Finding and trigger | Correction and evidence |
| --- | --- | --- |
| P1 | Pause halted ball physics but allowed batter/fielder animation, running, and throws to progress. A paused delivery could still score or finish. | Freeze those updates and ignore shot/run/clip input while paused. Game regressions reproduce the old failure and check pause/resume during run-up, pickup, and throw. |
| P1 | Completing a run before a boundary awarded five for a four and could incorrectly change strike. | Use the greater boundary/running allowance, rather than adding them. Check four/six after one run and a running allowance of five including a crossed run. |
| P1 | A legal catch after completed runs kept those runs and could replace the non-striker. | Clear running scores/strike changes on a legal catch; preserve the no-ball case. Both branches are covered. |
| P2 | The analyzer collided with the stance bat before the selected shot's input time, producing false timing results. | Only sweep after input, including inputs between physics ticks. The regression uses an overlapping blade and a timing step that does not align to the fixed tick. |
| P2 | Misses reported a contact time. Launch angle reported the intended angle before adding bat velocity. | Leave missed contact metrics blank; derive angle from the final outgoing velocity. Checks include miss records and upward bat movement. |

The boundary and caught-scoring corrections follow Laws 19.7 and 33.4 in the [MCC 2026 Laws](https://www.lords.org/getmedia/a4ef9f77-2a25-4f5b-a286-4601f08e6334/Laws-of-Cricket-2017-Code-4th-Edition-%282026%29_5.pdf).
