# Cricket 07 gameplay research

Research for the Super Cricket camera and feedback pass, 7 October 2026. This combines the installed PC copy's readable support material with a producer diary and contemporary PC reviews. The local game reached its title screen but did not advance past “Click to continue” in this Windows 11 session, despite mouse and keyboard input; the in-match menus and camera switches therefore could not be observed directly.

## Installed copy

The installation at `C:\Program Files (x86)\EA SPORTS\EA SPORTS(TM) Cricket 07` includes `Support\en-uk\readme.txt` (dated 6 September 2006), `Support\config.xml`, `Data\controltypes.csv`, the executable, and packed archives (`data.gob`, `un*ep.vp6`, and others). The help files are installation/display troubleshooting, not a gameplay manual or camera guide. `controltypes.csv` is a controller-detection/button-layout table; it does not contain the keyboard gameplay map. A targeted search of the install and its matching Documents save folder found no separate plain-text key map.

The readme lists a keyboard as a required input, says the mouse navigates the interface, and says Esc opens the pause menu. It recommends supported analog controllers for the game's tutorial button call-outs. It explicitly warns that some keyboards can lose control when multiple keys are pressed and that two players cannot both select keyboard controls. This is direct evidence to test chorded batting inputs on the physical keyboard rather than assume every key combination registers. The readme recommends practice nets to learn shots and timing, varying shots/directions, and run assist to judge running; it also says missed shots or being hit reduce confidence. For bowling it recommends varying line/length/field and matching spin to pitch and weather. The listed supported operating systems are Windows 2000 and XP; that makes compatibility a plausible reason for the previously stalled title prompt on Windows 11, but this remains an inference, not a confirmed diagnosis. The current computer-use surface returned no native application windows, so this pass could inspect the installed support files but could not re-enter the live match.

## Batting and onboarding

EA described Century Stick as an attempt to reduce the inputs needed for a basic batting action while retaining a deeper mode. In the default scheme, the right stick determines the stroke, direction, and timing in one gesture; how far it moves also controls shot power. The advanced scheme uses the left stick for crease movement and manual front/back-foot selection, while the right stick remains responsible for the shot. Triggers add loft and advancing down the pitch. Easier difficulty uses wider timing windows; higher difficulty and less confident/lower-order batters make timing and placement harder. [Producer diary #1](https://worthplaying.com/article/2006/11/2/news/37478-cricket-07-ps2pc-developer-diary-1/)

A PC review describes the same left-stick placement / right-stick shot-and-power split, notes the optional batting timing gauge, and explains that the sweet spot varies with batter skill. It also characterizes running as a single-button action. GameSpot likewise describes the optional early/on-time/late timing gauge and a batting loop that rewards timing and placement; its review calls out the bowling target cursor as overly sensitive. This is a useful caution: expose intended line and length clearly, but do not copy an unnecessarily twitchy cursor. The installed readme's emphasis on nets and run assist supports teaching these skills in short practice loops before expecting a player to use them in a full match. [PC review at GameFAQs](https://gamefaqs.gamespot.com/pc/935545-cricket-07/reviews/110832), [GameSpot review](https://www.gamespot.com/reviews/cricket-07-review/1900-6162251/)

## Cameras and in-game information

The producer said the default batting view was widened to keep the bowler's approach visible and build anticipation before release. Two reverse-perspective options face the approaching bowler. For the closer behind-batsman camera, EA made the batter and wicketkeeper semi-transparent because they otherwise hid the pitch-point marker. A separate Flip Cam changes sides for left- and right-handed batters. The fielding view was widened again so the player could read more of the outfield and make shot/run decisions. [Producer diary #3](https://worthplaying.com/article/2006/11/13/news/37744-cricket-07-ps2pc-developer-diary-3/)

The same diary describes the Picture-in-Picture panel as gameplay information: it helps judge whether a run is available, shows the bowler side-on during the approach, and shows the batter's shot in real time. A field radar lets the user adjust placement without pausing. The optional timing gauge is off by default and can be enabled in pause settings. This makes the important pattern a camera plus a small amount of contextual information, rather than relying on a single wide view or a dense instruction block.

EA's product page independently summarizes the same presentation goals: a reworked broadcast camera gives a wider view, behind-the-stumps views provide a more natural batting perspective, and picture-in-picture, a timing gauge, a running indicator, and a radar help with decisions. The producer diary adds the implementation detail that the close reverse view used semi-transparent batter and keeper models so the ball's pitch marker remained visible. Together, these sources point to offering distinct useful views and keeping the delivery, pitch point, and player feedback readable in each one, rather than treating zoom alone as the camera solution. [EA Sports Cricket 07 product page](https://www.ea.com/fi-fi/games/cricket/cricket-2007), [producer diary #3](https://worthplaying.com/article/2006/11/13/news/37744-cricket-07-ps2pc-developer-diary-3/).

## Bowling and running

Contemporary PC coverage describes bowling as choosing a delivery, watching a pace meter during the run-up, and stopping it within the permitted range; exceeding the cap produces a no-ball. The player also guides a pitch-point marker to set line and length. The same review criticizes the target cursor as too sensitive and easy to misplace. The useful design idea is visible pace/line/length intent with a clear outcome; the exact cursor sensitivity and timing pressure should not be copied. [PC review at GameFAQs](https://gamefaqs.gamespot.com/pc/935545-cricket-07/reviews/110832)

EA's diary and the PC review both describe the field radar and simple running prompt. They also show how cricket information can stay phase-specific: batting direction and shot, bowling selection and target, then whether a run is safe after contact. The review notes that Cricket 07 did not provide a return action after a mistimed running call, so our safer one-button repeat/turn-back behaviour should remain an intentional improvement.

## Application to Super Cricket

The response to the latest keyboard retest keeps these lessons grounded in playability:

- The 2006 EA producer says Cricket 07's wide default was deliberately designed to preserve the bowler's run-up and anticipation. It also shipped reverse views facing the approaching bowler, including a behind-batter view and a handedness-flipping variant. The behind-batter view used semi-transparent batter and keeper models because they otherwise hid the pitch marker. The fielding camera was deliberately wider to preserve field context. [Producer diary #3](https://worthplaying.com/article/2006/11/13/news/37744-cricket-07-ps2pc-developer-diary-3/)
- The same diary describes contextual picture-in-picture: the bowler from the side during the run-up, the batter's live shot, and whether a run is available; a radar supported field changes during the match. An optional timing gauge taught the shot window. These overlays carry gameplay information in context rather than asking a player to infer a tiny world-space cue.
- Step 57 defaults a human batter to a closer behind-striker view, uses a 40-degree camera lens for batting and bowling role views, and preserves wider broadcast and square-leg alternatives on V / left-stick click. A completed ball keeps a larger role-labelled result card; during play a high-contrast banner says whether the human made quality contact or how close the human bowler landed to aim. The ordinary HUD is shorter so it hides less of the bowler and pitch.
- The keyboard retest still found the role views too distant and the live feedback too easy to miss. Step 59 moves the default views to closer shoulder offsets, exposes Page Up/Down zoom during play, centers the live result banner, and holds contact/bounce feedback longer. This is a usability iteration to retest, not evidence that the new framing is already preferred.
- The installed readme and available developer diary/reviews contain more detail than the shipped `controltypes.csv`, but the UI could not be entered in this Windows 11 session. Step 57's captures were inspected locally; owner keyboard validation is still needed before calling the camera and feedback legible.

The next Cricket 07-inspired gaps are the batting timing aid and guided nets, clearer pitch-point visualization from the close reverse camera, and a fielding/run-availability cue. Bowling should gain an understandable pace/accuracy decision without bringing back a twitchy target control. For keyboard use, keep essential actions easy to execute and validate simultaneous key combinations on a real keyboard; the installed readme specifically warns about key buffering. Step 52 calibrates the result-card timing band against analyzer-measured best-contact delays; human playtesting still needs to confirm that the labels are understandable and helpful.

## Follow-up source cross-check

The producer diary provides a concrete camera principle for the latest keyboard findings: Cricket 07 made its default batting view wider specifically to show the bowler's run-up and preserve anticipation. It kept two reverse-perspective views available for players who preferred to face the bowler from the batter's end; one made the batter and keeper semi-transparent so they would not hide the pitch marker, while Flip Cam changed sides with batter handedness. Its default fielding view also stayed wide enough to retain the developing play. [EA producer diary #3](https://worthplaying.com/article/2006/11/13/news/37744-cricket-07-ps2pc-developer-diary-3/)

The contemporary reviews cross-check two details relevant to our feedback work: Cricket 07's optional timing gauge identified early, on-time, and late inputs, while bowling combined delivery choice, a pace meter, and a pitch-point marker. One PC review criticized that marker as too sensitive and the pace/line task as frustrating. This supports keeping our visible target and measured outcome while making the input forgiving; reproducing the old cursor's sensitivity would repeat a documented usability problem. [GameSpot review](https://www.gamespot.com/reviews/cricket-07-review/1900-6162251/), [PC review at GameFAQs](https://gamefaqs.gamespot.com/pc/935545-cricket-07/reviews/110832)

Step 61 applies the camera lesson as a compromise: it widens the existing behind-striker role view to frame both wickets and the approach, while keeping zoom and the broadcast/square-leg alternatives. It does not yet add Cricket 07's separate close behind-batter transparency treatment or handedness-flipping Flip Cam.

Additional details checked directly in the installed PC copy at `C:\Program Files (x86)\EA SPORTS\EA SPORTS(TM) Cricket 07`:

- `Support\en-uk\readme.txt` explicitly mentions the Behind Batsman and Flip camera views. It warns that semi-transparent player models may fail on an ATI Radeon 7500, an implementation caveat for any future see-through-player treatment.
- The readme warns that multi-key presses can lose input on some keyboards, recommends practice nets for learning shot choice and timing, and recommends run assist to judge running. This supports keeping keyboard actions individually easy to press and verifying real keyboard rollover before adding shot chords.
- `Data\controltypes.csv` is a controller-detection/layout table, not the PC keyboard gameplay map. The installed help pages focus on installation/display troubleshooting; this copy does not provide a plain-text gameplay manual.
- A previous attempt to enter a live match in this Windows 11 setup stalled at the title prompt, so in-game camera menus and overlays have not been independently inspected here. That limitation does not affect reading the installed readme or the published producer diary.

The producer's camera explanation is especially useful for interpreting the feedback: the wider default view was intentional so a player could watch the bowler approach and anticipate release. Cricket 07 also offered reverse views for users who preferred to face the bowler, including the transparency-assisted Behind Batsman view and handedness-flipping Flip Cam. The wider fielding view preserved context. Its picture-in-picture showed the bowler side-on during the approach, the batting stroke live, and whether a run was available; its optional timing gauge and field radar added phase-specific information. [Producer diary #3](https://worthplaying.com/article/2006/11/13/news/37744-cricket-07-ps2pc-developer-diary-3/) and [EA's Cricket 07 product page](https://www.ea.com/en-au/games/cricket/cricket-2007) corroborate those features.

The design implication is not to zoom every camera equally. Batting, bowling, and fielding need different views; an action-focused view should make the active player and ball readable, while an alternate wide view preserves the run-up and field. Feedback should be a persistent, high-contrast callout in unused HUD space, paired with world markers only when they can be seen. Cricket 07's optional early/on-time/late gauge supports the current timing cue, while GameSpot's contemporary review criticizes the bowling target cursor as overly sensitive; keep the target visible and forgiving rather than copying its twitchiness. [GameSpot review](https://www.gamespot.com/reviews/cricket-07-review/1900-6162251/)

Remaining reference-inspired gaps are the contextual picture-in-picture/run-availability cue, handedness-aware Flip Cam, guided practice nets, and broader animation/presentation coverage. Step 66 still needs keyboard validation before its camera and feedback are considered resolved.
